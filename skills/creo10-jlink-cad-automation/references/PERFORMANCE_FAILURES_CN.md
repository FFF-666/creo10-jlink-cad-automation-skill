# 性能优化与失败路径

## 1. 先测量，再优化

至少分别计时会话连接、模型打开/复制、参数读写、草绘/特征、批量循环、再生、保存、导出、报告和总耗时。第一次 JVM/Creo 运行只作预热；稳定运行至少 3 次并报告中位数。

先排序最大的三个阶段，只实施一组可验证改动。每轮比较相同输入、相同验证门和相同导出选项。

## 2. 低风险优化顺序

1. 缓存 Session、Model、Parameter、Feature 和选择对象。
2. 配置文件只读取一次。
3. 批量设置参数，最后完整再生一次。
4. 循环内禁止 Save、Window Activate、Repaint、弹窗和重复导出。
5. 全部验证通过后只保存一次。
6. 导出放到最后，并允许关闭非必要预览。
7. 日志缓冲写入，不在每行 `flush`。
8. 重复几何改用 Pattern/Relations。
9. 固定拓扑改用参数化模板，不让 Java 每次从零画完整模型。

球体真实基准中，关闭非必要预览导出后，总耗时中位数从 `940.708 ms` 降到 `451.460 ms`，约 `2.08×`，而 STL 哈希和全部 Creo 校验保持一致。这证明应优先移除无价值的导出，而不是牺牲最终再生和质量验证。

## 3. 本机已遇到的失败与处理

### `XToolkitBadContext`

场景：在 J-Link 启动回调中、当前/活动模型为空时调用 `ExecuteFeatureOps` 删除或抑制特征。

处理：不要在冷启动回调反复重试。等待用户提供稳定活动模型上下文，或将操作改为模板副本/后续明确命令。一次受控重试仍失败就停止。

### `XToolkitNotFound`

场景：在同一启动回调中直接检索不存在或不可见的本机模板。

处理：只读确认模板路径、类型、名称和会话工作目录；找不到就不要猜名称。参数化模板/UDF 必须先独立创建并验证。

### `ORDER_DEBUG` trail 循环

场景：为等待上下文反复冷启动 Creo/J-Link，生成巨量 trail 和无效等待。

处理：停止循环，保留一次失败证据，检查进程和日志；不要用更多冷启动掩盖上下文问题。大型 trail 不应进入 Git。

### `XToolkitFound`

场景：同一 Creo 会话重复导入相同模型名。

处理：每次测试使用唯一模型名和新输出目录，或在可控上下文正确清理已加载模型；不要覆盖已有输出。

### JAR 被占用

场景：J-Link JVM 正在加载应用 JAR，导致构建无法覆盖。

处理：停止辅助应用并关闭对应测试会话后再构建；不要强删或覆盖被占用文件。

## 4. 注册与代码的已知清理项

以下是已实现或发现但未单独回归的事项，不得当作已验证修复：

- `enable_jlink true` 在一个真实 `std.out` 中被 Creo 10 报告为无效关键字；移除后的独立回归尚未完成。
- 一个 `protk.dat` 的 `text_dir` 目录不存在，但应用未用文本资源而仍成功；修正后尚未单独回归。
- 球体配置中的 `diameter.mm` 尚未驱动源码常量；当前 50 mm 由 Java 常量决定。
- 二进制 STL 路线仍生成未采用的 IGES staging 文件；清理后尚未回归。
- 免费 J-Link/pfc 的原生 Sketch 创建边界尚未突破；不要把导入曲线称为原生 Sketch。

## 5. GUI 备用路线

只有 API、模板、UDF、Pattern 和中性导入都不能满足具体操作，并且用户明确授权后，才能使用 GUI。先记录窗口、模型、单位和工作副本；禁止坐标盲点；每个关键步骤后验证状态；仍必须做最终再生、回读和文件验证。
